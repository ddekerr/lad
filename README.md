# Лад

Веб-застосунок для музикантів: база пісень з текстом і акордами, плейлисти під музичні ролі, персональні копії, транспонування, режим сцени. Адаптивний (телефон, планшет, комп'ютер), інтерфейс англійською за замовчуванням і українською.

## Швидкий старт

Потрібні Node.js 22 (Linux-версія, у WSL не Windows-ова) і Docker з Compose.

```bash
npm install                   # заодно генерує Prisma-клієнт
npm run db:up                 # PostgreSQL у контейнері на localhost:5432 (значення в .env.development)
cat > .env.local <<EOF2
AUTH_SECRET=$(openssl rand -base64 32)
SUPER_ADMIN_EMAIL=твоя@пошта
EOF2
npm run db:migrate            # створює таблиці
npm run db:seed               # ролі й три демо-пісні
npm run dev                   # http://localhost:3000
```

Продакшен-змінні описані в `.env.example`; локальній розробці вони не потрібні.

Без налаштованого SMTP код для входу друкується в консоль, де запущено `npm run dev`. Увійди поштою з `SUPER_ADMIN_EMAIL`, і ти отримаєш права адміна й супер-адміна.

## Робота з гілками й перевірки

`main` захищено: у нього не можна комітити, пушити чи зливати локально. Порядок такий:

1. Працюй у гілці (`git switch -c feature/назва`) і пуш її на GitHub.
2. GitHub сам відкриє пул-реквест у `main` і запустить перевірку `check` (ESLint з межами шарів, типи, тести) та окрему `build` (збірка).
3. Коли `check` зелена, зливай пул-реквест кнопкою на GitHub. Поки вона червона чи ще йде, злиття заблоковано.
4. Локальний `main` лише оновлюй: `git switch main && git pull --ff-only`.

Те саме локально перед пушем: `npm run check` (і `npm run build`); форматування: `npm run format`. Git-хуки з `.githooks` підключаються самі в `npm install`.

## Статус

Готово: каталог і перегляд пісні, транспонування, сетлісти й спільна сцена, вхід (Google й email-код), ролі й права, плейлисти, персональні копії з оновленням з оригіналу, редактор пісень, імпорт із JSON.

Далі: перевірка в живому середовищі (`npm install`, міграції, e2e-тести), партії для інструментів (див. [посібник](docs/musicians-guide.md), розділ 12), імпорт в інших форматах.

Код розроблявся без запуску Next.js і Prisma (у середовищі розробки був закритий npm), тому перший повний прогін може виявити дрібні помилки.
