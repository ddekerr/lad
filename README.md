# Лад

Веб-застосунок для музикантів: база пісень з текстом і акордами, плейлисти, персональні копії, режим сцени. Адаптивний (телефон, планшет, комп'ютер), інтерфейс англійською за замовчуванням з перемикачем на українську.

Вимоги, схема БД і структура бекенду лежать у Project «Лад» (`lad-functional-spec.md`, `lad-db-schema.md`, `lad-backend-spec.md`, `lad-brand-spec.md`).

## Стек

Next.js (App Router, TypeScript), Tailwind CSS 4, PostgreSQL + Prisma, nodemailer для листів.

## Запуск

```bash
npm install
cp .env.example .env          # заповни AUTH_SECRET і SUPER_ADMIN_EMAIL
npx prisma migrate dev --name init
npm run db:seed               # ролі й три демо-пісні
npm run dev                   # http://localhost:3000
```

Перший вхід у розробці: без SMTP код для входу друкується в консоль, де запущено `npm run dev`. Вкажи свою пошту в `SUPER_ADMIN_EMAIL`, увійди нею, і ти отримаєш права адміна й супер-адміна.

Тести: `npm test`. Типи: `npm run typecheck`.

## Статус

Етап 1: каркас, бренд-тема, EN/UK, схема БД, каталог, перегляд пісні, транспонування акордів, режим сцени, публічне API пісень.

Етап 2: вхід через email-код і Google, сесії на 1 місяць, профіль, матриця прав, адмінка ролей (Admin), довідник музичних ролей (супер-адмін), підрахунок наслідків перед зняттям музичної ролі.

Етап 3: плейлисти в контексті музичної ролі або «без ролі», персональні копії пісень (нотатки, зсув тональності, власні правки), одна кнопка «Оновити згідно з оригіналом», «Залишити як власну», режим сцени з переходом між піснями плейлиста, порядок пісень стрілками.

Етап 4 (поточний): редактор пісень для ролі Editor: додавання, редагування з живим переглядом акордів, м'яке видалення; `version` зростає лише при зміні вмісту, тож копії користувачів отримують стан «оригінал оновили». API: `POST /api/songs`, `PATCH`/`DELETE /api/songs/{id}`.

Далі: перевірка в живому середовищі (npm install, міграції, e2e-тести), швидкість входу, імпорт пісень.

## Рішення, що відрізняються від backend-spec v0.2

- Сесія це один непрозорий токен у httpOnly cookie з терміном 1 місяць; у БД лише його хеш (таблиця `refresh_tokens`). Окремого короткого access-токена немає: перевірка йде по БД на кожен запит, відкликання (вихід) миттєве.
- Ролями в API керують за `roleId` (як у специфікації); довідник музичних ролей має ще `GET /api/roles/{id}/impact`.

## Примітки

- Транспонування акордів (`src/lib/chords`), права (`src/lib/auth/permissions.ts`), хеші кодів і словники покриті тестами.
- Код написано без запуску Next.js і Prisma (у середовищі розробки був закритий npm), тому перший `npm install`, `migrate` і `dev` можуть виявити дрібні помилки.
